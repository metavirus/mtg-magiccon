# POC Build Tranches

Updated: 2026-08-04  
Status: Tranche 1 accepted; Tranche 2 accepted; Tranche 3 implemented; retrieval cluster partially implemented

## Purpose

Build the product in short, reviewable slices so interaction, density, and information hierarchy can be corrected before adjacent surfaces inherit a weak pattern. Each tranche ends with a live desktop and phone review. Acceptance of one tranche authorizes only the next listed slice, not the rest of the product.

## Tranche 0 — working baseline

Current proof:

- left-anchored fluid desktop canvas;
- recomposed 390px mobile layout;
- compact but readable typography and controls;
- local read-only owner preview separated from real authentication;
- one Black Lotus Source → Observation → Occurrence → Decision → Itinerary path.

Exit gate: accept the shell density and interaction scale. Magic-link persistence remains a separate defect and must be fixed before real owner writes are treated as production-ready.

## Tranche 6 — Notes, Activity, and monitoring-alert intake

Implementation checkpoint (2026-08-04): complete for review as fixture-backed UI. Home now has a compact timely-signals strip, Notes is a working human-authored note surface with context backlinks, and Activity has All / Changes / Sources / Personal streams plus alert cards for site, newsletter, and email observations. The Activity side panel records the monitor intake contract future agents can target. No live Gmail monitor, newsletter crawler, official-page watcher, schema expansion, or automatic normalization was added.

MVP/POC should be ready to receive future monitoring alerts before any monitor exists. The first implementation is an intake/display contract, not automation:

- one alert shape that can represent Gmail receipts, newsletter posts, official-page changes, and manual observations;
- clear source separation: publisher/source wording, observed fact, AI summary, and personal decision remain distinct;
- Home can surface rare consequential alerts, while quiet or already-resolved observations stay in Activity;
- Activity can filter alert streams by All, Changes, Sources, and Personal, with rapid related changes collapsed into an expandable burst;
- Notes can attach to the alert, source, event, receipt, place, or item that caused the thought;
- every alert is clickable back to its object context and preserves retrieval/check time plus source URL or message reference where available;
- future monitoring agents can write reviewable observations into this contract, but cannot silently normalize, overwrite, or decide.

Stop before building the Gmail monitor, newsletter crawler, official-site watcher, full artifact storage model, or daily AI recomputation. The goal is a landing zone that makes those future monitors safe and useful.

## MVP/POC finish path

The operational glide path is now detailed in `docs/POC_FINISH_GLIDE_PATH.md`. That document controls how future agent-discovered news, email, site changes, and manual observations land in Home, Activity, Notes, Wallet, Trip, Explore, Calendar, or Map without becoming automatic canonical facts.

The remaining MVP/POC work should converge rather than expand:

1. **Phone preview hardening:** confirm GitHub Pages opens reliably on iPhone, mobile navigation works, and the home-screen icon is usable.
2. **Landing-route fixtures:** add representative site/newsletter/email/travel/note alert fixtures that demonstrate the routing contract without live automation.
3. **Prove the trust-slice loop:** exercise one source-revision reconciliation path and confirm the changed fact is visible without erasing prior evidence or the owner's decision.
4. **Prove offline retrieval:** verify the owner-bound critical view can reopen offline with visible freshness and no offline writes.
5. **Keep auth persistence quiet:** Google OAuth is the live-auth path; do not spend more magic-link quota casually.
6. **Run tiered handoff validation:** use `docs/ANTI_WASTE_OPERATING_MODE.md` so small UI work stays small, public preview work proves the public URL, and data/auth/database work still gets the full trust gate.

## Cross-tranche rules

- No tranche begins until the prior live desktop and phone review is accepted.
- Representative fixtures are small and visibly noncanonical.
- No broad ingestion, monitoring, or schema expansion merely to make a screen look populated.
- Build behavior before polish, but do not defer density and responsive composition as cleanup.
- Record rejected patterns so later surfaces do not reintroduce them.
