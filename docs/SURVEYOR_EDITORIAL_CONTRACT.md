# Surveyor editorial closure

Updated: 2026-09-19

Article coverage correction: inspect every discovered article from the approved index in the same run. There is no article-count or link-count cutoff. Retain the official-host/path allowlist, per-response byte limit, and request timeout; a failed fetch remains explicit partial coverage and holds acceptance under the failure policy. Older references below to deferred batches/rotation describe the superseded implementation, not permission to stop early. Regression coverage must include more than twelve articles completing in one run, even when legacy count settings are supplied.

Useful official convention news belongs on Home even when it is not urgent. Recognized changes to guests, creators, programs, maps, catalogs, pickup, accessibility, or similar planning interests receive a normal announcement card. New links prove that a resource was linked, not that a catalog contains inventory. Source excerpts and links stay attached. Home announcements expire after seven days from first detection; routine sellouts expire after 24 quiet hours. Rechecking never renews their age.

An unrecognized change is `pending_editorial`, never automatically noise. Its finding remains internal to the agent and its closure manifest names the exact fingerprint. Staging holds the baseline and uploads that manifest. The heartbeat must inspect the report and source, make the editorial judgment, and finish the work without asking Kavi to classify it.

To resolve pending editorial work, add an entry to `monitoring/editorial-decisions.json` keyed by the exact finding fingerprint. The value requires `disposition` (`home` or `noise`) and a concrete evidence-backed `reason`; `home` also requires a concise `title` and `summary`. Run the checks, publish the bounded decision, and replay the retained report using `daily-surveyor.yml` and `replay_run_id`. Replay proves the consequence; a subsequent normal cloud run accepts the exact current baseline. Changed evidence receives a different fingerprint and must not inherit an old decision. Noise requires an actual reason such as unchanged substantive content with navigation reorder, not failure to match a rule.

Official inbox-only public announcements use `monitoring/editorial-announcements.json`: an array of reviewed `id`, `title`, `summary`, `reason`, and `sourceUrl` records. The source URL must be a plain official MagicCon URL without tracking queries. State the newsletter date and source in the synopsis or reason where needed. Never include raw email, recipient addresses, message IDs, personal tracking links, receipts, or account details. Publish the reviewed input and run the normal cloud survey. Its cache deduplicates the input, and the same findings and Home verification path handles it. Do not add new runtime cards to `public/monitoring-intake.json`; existing cards there are transitional compatibility data.

Home closure requires an exact content/status/destination readback and the app's Home eligibility checks. A stored record alone is insufficient. Read/archive choices remain respected. Unit scenarios exercise guest wording without announcement keywords, a map PDF link, pickup changes, unknown editorial work, false closure, and expiry; browser checks exercise the resulting app view.

Coverage is separate from consequence closure. Failed article fetches fail the run and hold the saved baseline. Every discovered allowed article is fetched in the same run; unfetched URLs remain explicit `partial` coverage, not routine deferred batches. The heartbeat must inspect both coverage and closure, resolve omitted/failed coverage within the bounded source policy, and report any remaining gap explicitly. A source not configured or discovered was not checked. Relevant linked detail pages must be reviewed and added to the watch set or deliberately excluded; an overview-page check is not proof of detail-page coverage.

The cloud report reconciles all current relevant Atlanta links, including previously existing links and relevant top-level overviews such as Guests, against configured sources and exact dated `detailCoverageExclusions`. Gaps persist until watched or explicitly excluded, and overall coverage remains `partial` meanwhile. Exclusions require a reason, review time and future review deadline, appear in the report, and expire back into gaps. The host/path allowlist remains bounded; nothing is recursively fetched. Unlinked/unconfigured pages remain outside the coverage claim.

New watched sources emit an initial-review catch instead of silently accepting their current contents. `initialReview` may supply a reviewed `home` or `noise` disposition only when both current main-content and link hashes match; changed bytes require exact editorial review. Existing links on a new source are not new announcements. Initial relevant article intake likewise requires review. Stage the initial snapshot, close the exact catch, then accept that report in the ordinary cloud lane. Useful existing facts may be summarized deliberately in the reviewed announcements input. Never publish copied prior-event schedules or interpret a placeholder/catalog link as inventory. See `docs/SURVEYOR_SOURCE_ONBOARDING_2026-09-19.md`.

Watched-page change detection uses the official page's `#main` content, its links, and labeled images instead of hashing global navigation and footer copy as substantive facts. Whole-page hashes and samples remain retained as source evidence. If the accepted cache predates content fingerprints, the surveyor upgrades it only when the old whole-page hashes still match; an already-changed page still takes the normal review path. If the content container disappears, detection falls back to the body rather than treating the page as unchanged.

The cloud surveyor reads current canonical Ticketed Play availability and writes only a missing row or a changed availability/source key. Quiet source confirmations remain dated in the authoritative survey artifact; an unchanged table row's `observed_at` is the last state write, not the most recent quiet check. A transition still requires an exact canonical state/key readback or retained source-evidence proof before closure and baseline acceptance.

LEAP inventory completeness and purchasable-event availability coverage are separate. A schedule card with only a disabled anonymous "Login to add to your schedule" control does not prove availability. The surveyor binds every schedule card to the current first-party MTG Festivals listing's unique `gtID` by exact normalized title, day, and start time; changed end times do not break identity, but an unmatched/duplicate current ID holds the baseline. The August static snapshot is seed-only, not the live identity basis. It then matches each purchasable schedule event to a unique product on LEAP's public checkout page by day, start time, and normalized title, with only reviewed exact title aliases. Checkout's quantity selector proves a purchase control; its SOLD OUT label proves a sellout. Bracket advancement-only rounds are explicitly `notApplicableCount`, not unknown purchase opportunities. An unmatched or ambiguous product holds coverage open (and an unmatched checkout product fails the check) rather than inventing availability. Initial checkout evidence corrects older ambiguous schedule observations without creating false reopening/sellout alerts. Subsequent checkout-to-checkout transitions are ordinary reportable changes. The report keeps every unresolved event under `ticketedPlay.availabilityCoverage.notCovered`; overall coverage is `partial` while any purchasable state remains unresolved.

Do not require Atlanta in an article URL or index label before fetching: generic newsletters can contain Atlanta news. Discover candidates only from the approved index and URL allowlist, inspect article content without shared navigation/footer, and distinguish inspected non-Atlanta content from uninspected candidates. Uncertain relevance remains editorial work. Fetch every eligible discovered article without an article-count cutoff. Fetch failures must not acquire successful-fetch timestamps or fingerprints.

A mixed-location article is not Atlanta-specific merely because it mentions Atlanta once. In particular, another convention's operational guide may end with an Atlanta badge promotion. Such articles require editorial review before either Home routing or canonical fact extraction; a reviewed exact-fingerprint decision can discard stale promotion without suppressing genuinely useful Atlanta sections. The Amsterdam guide caught during live validation is the regression case for this boundary.
