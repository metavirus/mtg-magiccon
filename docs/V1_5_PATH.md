# Version 1.5 Path

Updated: 2026-08-04  
Status: Accepted direction; trust tranche active

## Outcome

Version 1.5 turns the fixture-backed POC into a trustworthy, self-refreshing personal companion. The POC already proved the main information architecture and visual language. Version 1.5 therefore prioritizes durable information flow, source reconciliation, authenticated continuity, and critical mobile retrieval over another broad round of screen construction.

Work proceeds on two tracks:

1. **Trust and intake now:** authentication persistence, revision reconciliation, offline proof, reviewed monitoring observations, contextual backlinks, and narrowly scoped private artifacts.
2. **Planning when evidence arrives:** manual ticketed-play capture first, then the production Plan workspace only after representative Atlanta inventory exposes the real data variation.

The forecast ticketed-play window is August 18-25. It is a planning clue, not an Atlanta fact, but it makes the trust and intake track time-sensitive.

## Tranche 1 — close the trust loop

### Scope

- Preserve authenticated mode across magic-link callbacks, refreshes, and installed-app launches.
- Exercise one reviewed source revision without deleting the prior observation.
- Keep publisher evidence, normalized occurrence, personal decision, and itinerary consequence distinct.
- Reopen the owner-bound critical view offline with visible freshness.
- Keep offline writes disabled.

### Acceptance

- One sign-in survives refresh without silently falling back to design preview.
- A second observation explicitly supersedes the first and both remain recoverable.
- Normalized changes do not silently alter the owner's planning state or itinerary.
- The cached critical view opens on the real iPhone with its saved time visible.
- State-changing controls are unavailable offline.

## Tranche 2 — durable reviewed monitoring intake

Replace the tracked JSON preview seam with a small owner-scoped observation inbox only after Tranche 1 passes.

The intake should retain source identity, exact reference, checked/retrieved time, useful wording or artifact pointer, AI summary, consequence rationale, suggested destination, attention level, review status, and supersession or contradiction links. The monitor may propose observations; it may not silently normalize facts, alter plans or preferences, or promote community chatter into publisher truth.

Home remains reserved for rare consequential signals. Activity carries review history. Findings should backlink into the affected Wallet, Trip, Explore, Calendar, Map, or other contextual object instead of becoming dead alert cards.

### Acceptance

- A real source or email finding reaches a reviewed observation without editing React fixtures.
- The observation opens its affected destination.
- Cosmetic or irrelevant findings can be dismissed without destroying evidence.
- Promotion into normalized state is a separate explicit workflow.

## Tranche 3 — narrow private artifact proof

Define private Storage only for the first approved artifact workflow. Use one badge order, one travel confirmation, and one purchase receipt as the proof set.

Preserve the original PNG or PDF separately from extracted metadata. Support a focused show-original or show-code mode, extracted line items and quantities, lightweight assignment and notes, correction of extraction mistakes, and explicit offline eligibility. Do not build a general mailbox archive.

## Tranche 4 — ticketed-play vertical slice

When Atlanta inventory appears, capture one representative event manually before broad ingestion. Preserve the source wording; translate it into time, duration, price/access, refund consequence, availability, format, structure, prizes, eligibility, and fixed/flexible/fuzzy timing; add a source-backed complexity rationale; express personal interest; and show the Calendar/Plan consequence.

Then capture one later wording or availability change. Only this real slice may authorize a broader event schema or automated inventory ingest.

## Tranche 5 — production Plan from real contention

Resume Plan only when representative Atlanta data exists. The first production scope is November 13-15, proportional time placement, visible overlaps, reversible Interested/Tentative/Committed/Purchased states, fixed and flexible events, Black Lotus inclusion, fuzzy tails, purchased financial anchors, concise consequence previews, Calendar handoff, and onsite agenda retrieval.

Do not add drag-and-drop scheduling, scenario solvers, automatic schedule generation, multi-user editing, or AI recomputation in this tranche. Chris and Juan may remain lightweight people attached to owner-managed plans.

## Tranche 6 — selective onsite hardening

- Redesign Wallet Home and Prize Tix mobile-first.
- Tune Activity density using real monitor output.
- Define a small offline pack for upcoming commitments, approved proofs, Trip facts, important notes, and confirmed places.
- Test real-device installation and retrieval.
- Later, run synthetic onsite scenarios for lost connectivity, next-location retrieval, showing proof, checking an event code, and seeing a changed schedule.

## Explicitly deferred

- broad visual polish;
- comprehensive MagicCon schema;
- general autonomous research or crawling;
- full interactive convention atlas;
- multi-user accounts, permissions, voting, chat, or live schedule sharing;
- offline writes or synchronization;
- sophisticated schedule optimization;
- extensive post-event functionality;
- further Prize Tix art iteration before the mobile interaction is settled.

## Immediate execution order

1. Fix authenticated-mode persistence and callback routing.
2. Prove revision reconciliation in code and tests.
3. Verify the cached critical view offline on the real iPhone.
4. Review the result before authorizing the Supabase-backed monitoring inbox.
