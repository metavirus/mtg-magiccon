# Artist ownership and source provenance cutover

## Contract

- Shared artist/card/printing identity, prices, and convention attendance stay shared.
- Holdings, collection profile counts, assessment/taste text, and source manifests belong to their owner. Browser clients have read access only; imports remain privileged.
- Printing UUIDs and signing choices are never regenerated by this cutover.
- `artist_collection_inventory` is the app's quantity source. Assessments and import batches now have owner predicates. Compound foreign keys prevent cross-owner provenance links.
- Source-record ordinals are one-based nonblank parsed CSV records **before** eligibility filtering, not physical line numbers. Source-observed/assessed dates remain null when unknown; importing today does not establish when an assessment was made.
- The production fallback no longer contains a real collection. The one public preview example has synthetic quantity/assessment. Legacy artist device snapshots are invalidated independently of Wallet and signing choices.

## Operating commands

`pnpm artist:seed-sql --owner <UUID>` generates the owner-aware full import SQL; it does not apply it. Explicit source names/paths are required when calling the exported builder directly. Attendance is never changed by this importer.

`pnpm artist:seed-sql --reconcile-only --owner <UUID>` generates the one-time, original-snapshot-guarded repair. It deliberately fails against an already-corrected or otherwise changed quantity digest instead of guessing. Source SQL stays ignored in `local-assets/artist-card-working/`.

`supabase/tests/artist_ownership.sql` verifies real owner/nonowner role behavior and grants in a rolled-back transaction. Run through the existing canonical database tooling.

The old fixture generator writes only ignored `artistCardCandidates.private.ts`, never the production module.

## Release sequencing

Additive owner tables and source reconciliation are applied. Deploy the new app read path before removing legacy shared quantity/local-image/profile-count columns. The reviewed cleanup SQL is in `.codex-local/artist_shared_cleanup.sql`; it refuses to proceed without private preservation. Full privacy completion requires that cleanup and deployed bundle verification, not merely hiding the Cards tab.

Out of scope: inventory editing UI, absent-from-next-snapshot deletion/reconciliation policy, signing completion/checklist, and redesign of card-art assessments. Existing git history/previously downloaded bundles cannot be retroactively made private by replacing the current bundle.
